# 添加演示视频

视频由项目维护者录制。本目录当前只包含接入说明，没有占位视频文件，也没有声称已经运行的播放器。

## 推荐录制内容

| 视频 | 建议展示 |
| --- | --- |
| 仿真运行 | 启动命令、参数、逐步执行和输出指标 |
| 联合动作 | 网格编号、时间步、价格乘子、匹配半径及输出表 |
| 数据管线 | 采集、构建监督样本、校验报告的完整流程 |
| 车辆跟随（如果已有可视化） | 明确展示所选司机/车辆及时间；与网格统计录像区分 |

录制时保留可读字号，避免将需要阅读的终端画面压缩得太小。当前仓库没有车辆跟随可视化前端，只有网格级仿真与输出表；若使用外部前端，说明其来源和数据连接方式。

## 方式一：GitHub 附件链接

在 GitHub 网页编辑根目录的 `README.md`，在演示区上传 MP4，使用 GitHub 返回的附件地址。删除“视频待录制”的说明并更新演示表格状态。

```markdown
### 仿真运行演示

在这里粘贴上传后 GitHub 返回的视频附件 URL
```

不预先填写虚构的附件地址。真实的附件地址会包含 GitHub 分配的 ID。

## 方式二：仓库文件与封面链接

如果要把视频作为仓库文件保存，可使用下面的路径：

```text
docs/media/
├── README.md
├── simulation-demo.mp4
└── pipeline-demo.mp4
```

仅在对应文件实际存在后，将根 README 的封面修改为：

```markdown
[![仿真运行演示](docs/assets/demo-cover.svg)](docs/media/simulation-demo.mp4)

[数据管线视频](docs/media/pipeline-demo.mp4)
```

封面链接是稳妥的播放/下载入口；不依赖 README 中自定义 `<video>` 标签的渲染。较长录像宜使用附件或独立存储，避免视频反复更新扩大 Git 历史。

## 封面

`docs/assets/demo-cover.svg` 是待录制展示区的设计封面，并非仿真截图。拿到录像后，可以替换为真实截图并在标题中注明视频展示内容。不要将不同实验的录像与数据指标混为同一次运行结果。
