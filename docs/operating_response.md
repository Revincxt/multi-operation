# 价格与接驾距离诊断

```bash
python3 -m diagnostics.operating_response --output experiments/operating_response
```

需要项目仿真依赖和 `matplotlib`。输出目录必须为空；不会覆盖既有数据，也不修改核心仿真逻辑。

## 实验

- 此入口默认仍为历史诊断配置：2015-05-18，05:00–10:00，263 个网格、1000 名司机，`utility_choice`，关闭空车调位；与当前六网格低密度采集不同。
- 价格扫描固定半径 1 km，半径扫描固定价格乘子 1；候选集合随 `src/env/actions.py` 更新，目前分别为 11 个价格和 10 个半径。
- 默认 seed 为 42、43、44，共 60 次仿真（两个扫描共用一组参考动作）。相同 seed 共享初始化，但动作变化后随机数消费路径会分叉，并非逐订单随机数严格配对。
- 所有网格在一次诊断中使用相同固定动作，以隔离参数影响。这不是替换原有逐网格随机探索，也不是优化策略。
- 实际接驾距离使用价格 1、半径 4 km 的派单结果，每 0.25 km 分箱，包含司机拒单和乘客取消，不只统计成功订单。

可通过 `--prices`、`--radii`、`--seeds`、`--workers`、`--simulation-steps` 等调整规模。只重画已完成实验的图：

```bash
python3 -m diagnostics.operating_response --output experiments/operating_response --plot-only
```

## 口径

| 指标 | 分子 / 分母 |
| --- | --- |
| 原有订单完成率 | 最终成功匹配数 / 候选订单次数；积压重试会重复计入分母 |
| 司机接单率 | 司机接受次数 / 平台派单次数；司机接受后乘客仍可能取消 |
| 平台收益 | 成功匹配订单的实际车费 × 25% 抽成，再求和；不是总车费或净利润 |
| 实际距离分箱成功率 | 箱内最终成功匹配次数 / 箱内派单次数 |

价格和半径图沿用数据管线的完成率定义。距离分箱不能沿用“候选订单次数”作分母：没有获得派单的候选订单没有接驾距离。因此距离图是**获得派单后的条件成功率**，不是整体订单完成率。

距离是当前仿真器的 Haversine 直线距离，不是道路行驶里程。分箱收益是该箱内的总收益，也受派单数量影响；CSV 另提供每次派单平均收益。距离图属于观察性关联，不能解释为单独改变接驾距离的因果效应。

所有总体比率均先汇总计数再相除，不直接平均网格比率。图示跨 seed 均值及 ±1 标准差，不是置信区间；单个 seed 分箱少于 20 次派单时不画其比率。保留原有时间边界，不额外清空期末队列，因此成功指匹配被双方接受，不要求本窗口内完成送达。

输入模式保持 `observed_requests`：低价可生成扩增需求，呼出数 / 原始需求数可能大于 1，不是概率越界。

## 输出

- `price_response.png`：价格乘子与三个指标。
- `radius_response.png`：匹配半径与三个指标。
- `actual_distance_response.png`：实际距离、派单条件成功率、司机接单率、分箱收益及派单样本量。
- `run_summary.csv`、`scenario_summary.csv`：逐 seed 数据与均值/标准差。
- `actual_distance_summary.csv`：基准价格、最大半径下的逐 seed 距离分箱数据。
- `runs/*/offers.csv.gz`：包含拒绝结果的逐次派单记录；同一订单重试可有多行。
- `runs/*/minute_counts.csv`：全城分钟级计数，用于复核分母。
- `manifest.json`、`runs/*/response_parameters.json`：配置、源码指纹和响应模型参数。

这些是单日期、当前模型参数下的机制诊断，不是现实需求/收益的校准结论。
