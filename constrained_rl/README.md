# 收益与服务约束：PPO-Lagrangian 试训

沿用 AR-PPO 的六网格联合价格／半径策略，以平台累计佣金为主目标，同时约束基准需求覆盖率和全队列等待成本。

本次是已有冻结权重上的小规模微调试验：约束组与收益对照组从相同 AR-PPO 参数开始、使用相同交互预算。它不等同于随机初始化训练的完整算法比较。原版框架和冻结权重独立保留。

## 指标与约束

- **基准需求覆盖率**：获得成功匹配的基准订单谱系数 / 同一计分需求群体的基准订单数。群体包括预热结束时仍等待的实际订单，以及计分期间的基准冒泡需求；计分期间价格响应产生的复制订单按其父订单计数，同一父订单最多计一次覆盖。它是被观察基准需求的覆盖代理，不是真实潜在市场需求满足率。字段名保留 `demand_satisfaction`。
- **等待成本**：计分期间所有实际排队订单新增的累计等待秒数 / 计分基准需求数，包含复制订单、后来取消及终点仍未服务者，排除预热已发生的等待和接驾时间。未服务谱系不会计入覆盖数。
- **收益**：计分期间成功匹配订单的平台佣金，沿用原有定义。

服务下限与等待上限由独立 F3 校准场景确定并写入协议。训练约束是 `E[已覆盖谱系数] / E[基准需求数]` 和 `E[等待秒数] / E[基准需求数]`，通过累计分子、分母计算，不对逐步比例求平均。两个拉格朗日乘子依据完整训练批次的约束偏差更新；违反约束时增加对应惩罚，满足约束时允许降低。

这是期望约束优化，并不保证每条仿真都满足约束。原有候选池完成率和仅匹配乘客平均等待时间继续用于评估，与上述新服务指标分开报告。约束目标可能牺牲部分收益；实际可行性与收益变化需在独立场景上确认。

## 输出与比较

默认两组各训练256条完整仿真，使用32条独立F3校准场景、32条成本预测头预热轨迹和50条封存测试场景：

```bash
python3 -m constrained_rl.train --output models/constrained_ppo_pilot_20261115 --workers 8 --device mps
```

输出目录存在时读取其冻结协议和断点；运行中发送SIGINT/SIGTERM会在当前批次结束后暂停。原有在线训练任务保持暂停。

`training_history.csv` 每批记录收益、服务率、等待成本、两个乘子及 PPO 诊断。`evaluation.csv` 保留每个环境种子的原六项指标和新指标的分子分母。

采用固定预算结束时的模型，与 F3、冻结 AR-PPO、同预算收益对照进行配对测试；测试集不参与阈值拟合或模型选择。

```bash
python3 -m constrained_rl.report <实验输出目录>
```

输出 `training_curves.png/pdf`、`test_comparison.png/pdf`、`policy_summary.csv`、`paired_statistics.csv` 和 `report.json`。置信区间以共同环境种子配对 bootstrap 10,000 次计算；单个初始化的小试不包含训练随机性的估计。服务指标按总分子／总分母重算每个 bootstrap 样本，避免与逐仿真比例的均值混淆。

对比图中的 `AR-PPO` 是微调前冻结模型，`PPO-R` 是同预算收益微调对照，`PPO-L` 是本次拉格朗日约束微调；服务图中的虚线表示独立校准后冻结的约束界限。

参考：[约束策略优化](https://proceedings.mlr.press/v70/achiam17a.html)、[拉格朗日约束更新](https://proceedings.mlr.press/v119/stooke20a.html)。本框架是当前场景的适配实现，不声称复现 CPO 或具有每轮可行性保证。

## 从随机权重长训练

```bash
python3 -m constrained_rl.launch_scratch --workers 8 --device mps
```

默认输出 `models/constrained_ppo_scratch100k_20261116`，约束组与收益对照组各训练100,000条完整仿真。两组从相同随机参数开始，使用全新优化器，不加载预训练权重，也不进行成本头预热；两个成本输出层初始为零。输入归一化、F3服务阈值及奖励尺度沿用冻结校准，学习率采用原在线从零训练设置 `3e-4`。

每16条完整仿真更新一次。前1、4、16次更新和此后每64次更新做独立验证；全部预算结束后，四个策略在100个封存测试种子上比较。旧AR-PPO仅在最终测试时读取，作为预训练参考。两组各采用一个训练种子，本次不包含多初始化不确定性估计。

`training_history.csv` 每批更新，包含收益、两个约束、乘子、KL、熵和三个价值预测的整段回报拟合指标；`evaluation.csv` 记录验证/测试，`progress.json` 记录当前进度。训练曲线与验证曲线定期导出PNG/PDF。

`constrained/latest.pt`、`revenue_control/latest.pt` 保存模型、优化器、采样位置、乘子和随机状态，验证节点另存策略快照。向 `progress.json` 中的PID发送SIGTERM可在当前批次后暂停；再次执行启动命令会续训。协议、初始化和源码快照均校验哈希，已有目录的训练预算以其冻结协议为准。
